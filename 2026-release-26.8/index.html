Small And Nice Features

Pipe operators

Write queries top-down, like in GoogleSQL — each step follows the previous:

FROM hits |> WHERE status = 404 |> AGGREGATE sum(hits) AS total GROUP BY path |> ORDER BY total DESC |> LIMIT 3;

— Each |> wraps the query before it into a subquery,
  so the result is the same AST as for nested subqueries — no new semantics.
— A query can now start with FROM, and SELECT is optional
  (defaults to SELECT *): FROM hits |> LIMIT 10 just works.

Developer: Alexey Milovidov.

GROUPS frame for window functions

The third frame mode of SQL:2011, joining ROWS and RANGE:

SELECT ts, price, avg(price) OVER ( PARTITION BY symbol ORDER BY ts GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW) FROM trades;

— In a GROUPS frame, boundaries count whole peer groups —
  sets of rows equal on the ORDER BY key.
— N PRECEDING = N peer groups before the current row's group,
  not N physical rows (ROWS) or an ORDER BY value distance (RANGE).

Developer: Nihal Z. Miaji.

Array subscripts and notHas

The subscript operator accepts an array of indexes:

SELECT ['a', 'b', 'c', 'd', 'e'][[1, 3, 5]]; -- ['a', 'c', 'e'] -- same as arrayMap(i -> arr[i], indexes)

And notHas — the negation of has for arrays, maps, and JSON:

SELECT count() FROM events WHERE notHas(tags, 'internal'); -- with a constant array, it is rewritten to `x NOT IN (...)`, -- so it can prune by the primary key index

Developers: folly, Nihal Z. Miaji.

mergedJSONPatch

An aggregate function that merges JSON values in the order of a sort key,
RFC 7396 style — the latest value of each path wins:

SELECT id, mergedJSONPatch(patch, ts) FROM changes GROUP BY id; -- ts 1: {"name":"alice","age":30} -- ts 2: {"age":31,"city":"Berlin"} -- result: {"age":31,"city":"Berlin","name":"alice"}

— The current state of an entity from a stream of partial updates.
— Works in AggregatingMergeTree — keep the state up to date on merges.

Developer: larryluogit.

Date32: years 0 to 9999

26.7 extended DateTime64. 26.8 extends Date32 to match:
the range grew from [1900, 2299] to [0000-01-01, 9999-12-31]:

SELECT toDate32('9999-12-31'); -- was clamped to 2299-12-31 SELECT toDate32('0001-01-01'); -- was clamped to 1900-01-01 SELECT toDate32('0079-08-24') + INTERVAL 1947 YEAR; -- 2026-08-24 — 1947 years after the eruption of Vesuvius

— Parsing and conversions accept the extended range
  instead of silently clamping to the old boundaries.

Developer: Alexey Milovidov.

More small things

— gini — an aggregate function for the Gini coefficient:
  SELECT gini(income) FROM households;

— VALID FOR — a shorthand for VALID UNTIL:
  CREATE USER app IDENTIFIED BY '...' VALID FOR INTERVAL 30 DAY;

— Column modifiers in any order:
  x UInt64 COMMENT 'id' CODEC(ZSTD) is no longer a syntax error.

— EXPLAIN SYNTAX returns one recoverable record:
  SELECT count() FROM (EXPLAIN SYNTAX ...) returns 1.

— system.mutations.finish_time — when a mutation completed.

— system.statements — documentation of every SQL statement.

Developers: Amirreza Akhondi, A. Milovidov, N. Mikhaylov, R. Schulze.

HTTP Interface

CREATE HANDLER

Define custom HTTP endpoints from SQL — no config editing:

CREATE HANDLER top_pages URL '/top_pages' AS SELECT path, sum(hits) AS total FROM hits GROUP BY path ORDER BY total DESC LIMIT 5;

$ curl http://server:8123/top_pages /page19 254500 /page18 254000

— Parameterized: {p:String} is filled from URL params, form fields,
  headers, or named regexp capture groups. INSERT handlers read the body.
— Persisted (locally or in Keeper) — handlers survive restarts and
  sync across replicas. ALTER/DROP HANDLER, grants, system.handlers.

Developer: Alexey Milovidov.

Tables as URL paths

The HTTP interface can serve tables by path — REST style:

$ curl 'http://server:8123/default/hits.csv?limit=3' $ curl 'http://server:8123/default/status=404/hits.csv' -- path filters $ curl 'http://server:8123/default/hits.JSONEachRow?status=404&hits>500' $ curl 'http://server:8123/default/hits.csv?order=hits+desc&page=2' $ curl 'http://server:8123/default/hits.csv.gz' -- compression

— New query-construction settings: select, filter, order, limit, page, …
— They compose with each other and with the classic query parameter.
— Off by default: the server-level http_allow_path_requests gates routing,
  and per-user settings enable each piece for chosen users only.

Developer: Alexey Milovidov.

Framing formats

One HTTP response stream can now carry everything: data, progress,
totals, profile events, server logs, and exceptions — multiplexed:

$ curl 'http://server:8123/?query=...&framing_output_format=EventStream' event: data data: {"number":"0"} event: progress data: {"read_rows":"3","elapsed_ns":"7496990",...}

— EventStream — HTTP server-sent events, consumable
  by the browser's built-in EventSource API.
— JSONEachPacketString / JSONEachPacketBase64 — a JSON object per packet.
— Live progress bars and streaming results without a custom protocol.

Developer: Alexey Milovidov.

HTTP interface, elsewhere

— default_session_user: the user for connections that do not specify one
  (was hardcoded to default) — per server, or per listening port;
  set it to an empty string to prohibit anonymous connections.

— 403 Forbidden is returned for ACCESS_DENIED errors
  (was 500 Internal Server Error).

— clickhouse-local answers CORS preflight requests,
  so SYSTEM START LISTEN HTTP makes it usable from a browser.

— Parsing requests with thousands of repeated parameters
  is no longer quadratic.

Developers: Alexey Milovidov, Schum, James.

Text Search

Tokenizers for every language

Four new tokenizers for the tokens function and text indexes:

SELECT tokens('ClickHouse是一个快速的开源数据库', 'chinese'); -- ['ClickHouse','是','一个','快速','的','开源','数据库'] — dictionary + HMM SELECT tokens('こんにちは世界。データベースです。', 'icu', 'ja'); -- ['こんにちは','世界','データベース','です'] — locale-aware Unicode segmentation SELECT tokens('C++ and C# are languages', 'splitByRegexp', '[^\p{L}\p{N}#+]+'); -- ['C++','and','C#','are','languages'] — tokens other tokenizers would break

— Also: japanese — the MeCab morphological analyzer (the dictionary
  is loaded from a path in the server config, checksum-verified),
  and keyword as an Elasticsearch-compatible alias for array.

Developers: Robert Schulze, Amos Bird, Jimmy Aguilar Mena.

Text indexes: faster answers

COUNT() is answered directly from the index cardinality metadata:

SELECT count() FROM docs WHERE hasAnyTokens(body, ['fox']); -- 1 million rows matched; rows actually read: 1

— Posting lists are now decoded lazily, at packed-block granularity,
  instead of being eagerly materialized into bitmaps.
— Optional cache for tokens missing from the index.
— The v2 on-disk format (with positions for phrase search) is the default;
  text_index_version controls it for rolling upgrades.

Developers: Elmi Ahmadov, Anton Popov, Rory Shanks.

Data Lakes & Integrations

BigQuery

A table function and a table engine for Google BigQuery:

SELECT corpus, count() FROM bigquery( 'my-project', 'samples', 'shakespeare', service_account_key = '{"type": "service_account", ...}') GROUP BY corpus; CREATE TABLE bq_events ENGINE = BigQuery('my-project', 'events', 'log'); INSERT INTO bq_events VALUES (...); -- writes work, too

— The structure is inferred from the BigQuery table schema.
— Includes public datasets.
— Auth: OAuth access token, service account key (JSON),
  or an OAuth client with a refresh token.

Developer: Alexey Milovidov.

Data lakes, elsewhere

— Snowflake Horizon: query Iceberg tables behind the Horizon catalog —
  and write to them through the catalog.

— AWS S3 Tables catalog: now with a working INSERT,
  and you can create your own tables.

— Puffin file format (Iceberg statistics files) —
  readable with file, url, s3, and friends.

— Concurrent Iceberg writes on a local disk: conditional writes
  make the snapshot compare-and-swap safe.

— Iceberg reads: the next manifest is prefetched while the current one
  is parsed; delete manifests are decoded concurrently;
  manifests without sequence_number (e.g. written by BigQuery) load fine.

Developers: Melvyn Peignon, Konstantin Vedernikov, Alexey Milovidov, Asya Shneerson.

The URL database engine

26.7 unified the url function. 26.8 finishes the job:

-- a table name can simply be a URL now: SELECT town, price FROM 'https://…/house_prices.parquet' ORDER BY price DESC LIMIT 3; CREATE DATABASE web ENGINE = URL('https://example.com/data/'); SELECT count() FROM web.`sales/2026.parquet`; -- resolved against the base

— Dispatches by URL scheme: file, http(s), s3, gs, az, hdfs — uniformly.
— It replaces Filesystem in the default database of clickhouse-local
  (with a file:// base), so plain file names keep working.
— s3_base / url_base settings resolve relative URLs.

Developer: Alexey Milovidov.

PostgreSQL, better together

psql now feels at home when connected to ClickHouse:

$ psql "host=… port=9005 user=pg dbname=default" default=> \dt -- lists ClickHouse tables default=> SELECT count() FROM hits WHERE path ~ 'page1[0-9]'; -- 5000

— PostgreSQL-style regexp operators: ~, ~*, !~, !~* — in any query.
— A failed query no longer terminates the psql connection.
— TLS to PostgreSQL everywhere (engine, function, databases, dictionaries):
  sslmode plus certificates — inline (sslcert_pem, masked like passwords)
  or as server-side paths in named collections.
— MySQL-compatibility columns in INFORMATION_SCHEMA.

Developer: Alexey Milovidov.

Observability & Operations

run_query_in_background

Fire and forget: the server accepts the query, returns immediately,
and runs it to completion — whatever happens to your connection:

INSERT INTO backup_table SELECT * FROM huge_table SETTINGS run_query_in_background = 1; -- returns instantly; the INSERT keeps running on the server SELECT query_id, elapsed FROM system.processes; -- track it

— For long INSERT … SELECT, CREATE TABLE … AS SELECT,
  CREATE MATERIALIZED VIEW … POPULATE — that must not die
  with a dropped connection, a closed laptop, or a flaky VPN.
— Track by query_id in system.processes and the query log.

Developer: Miсhael Stetsyuk.

system.user_query_log

Every user can see their own query history —
without access to the full query log:

-- as user 'analyst', with no special grants: SELECT user, query FROM system.user_query_log LIMIT 1; -- analyst │ SELECT count() FROM default.hits — own queries only SELECT count() FROM system.query_log; -- ACCESS_DENIED — as before

— Debug your own slow queries without asking the DBA.

Developers: Yue Ni, Alexey Milovidov.

Union system log tables

System logs rotate, and every replica keeps its own —
now one table can query all of them at once:

-- with the create_union_system_log_tables config section: SELECT … FROM system.all_query_log; -- the current table + rotated versions + all replicas of the cluster

Also, remote, cluster, and friends accept a trailing SETTINGS clause:

SELECT … FROM clusterAllReplicas('default', system.query_log, SETTINGS skip_unavailable_shards = 1);

Developer: Alexey Milovidov.

The introspection port

What is my server doing while it starts up or shuts down?
A native protocol listener that opens before tables are attached
and closes only after they are detached:

$ clickhouse client --port 9099 -- during a slow startup SHOW PROCESSLIST; SELECT * FROM system.stack_trace;

— Watch table loading, catch shutdown hangs, instrument code paths.
— The default shutdown_wait_unfinished grew from 5 to 120 seconds,
  so the server no longer force-exits in the middle of a graceful shutdown.

Developer: Miсhael Stetsyuk.

Keeper news

— On-disk storage 🧪: a custom LSM tree instead of keeping
  the whole state in memory — with similar performance;
  the data can even live on S3 (s3_plain disk).

— A Cluster tab in the Keeper HTTP dashboard: Raft membership
  as a topology graph with health colors, lag, and priority.

— Faster: changelog reads with less lock contention and background
  pre-decoding; startup reads changelog files concurrently;
  fsync batching (min_time_between_fsyncs_ms).

— ZooKeeper-compatible election metrics in mntr:
  zk_leader_uptime, zk_sum_election_time, …

Developers: Michael Kolupaev, yanglongwei, Antonio Andelic, Maxim Orlovsky.

Atomic POPULATE

CREATE MATERIALIZED VIEW … POPULATE used to lose rows
inserted while the view was being filled. Not anymore:

-- 30 concurrent INSERTs racing the CREATE: CREATE MATERIALIZED VIEW mv ENGINE = SummingMergeTree ORDER BY () POPULATE AS SELECT sum(v) AS total FROM events; SELECT (SELECT sum(v) FROM events) AS source, (SELECT sum(total) FROM mv) AS materialized; -- 20300000 = 20300000 — nothing lost, nothing duplicated ✓

— The view subscription and the snapshot of existing data are set up
  atomically, under a brief lock on the source (local inserts, MergeTree
  and Memory sources; on by default: materialized_views_populate_atomically).
— POPULATE now also works with TO — to backfill the target.

Developer: Alexey Milovidov.

JOINs

IEJoin: fast inequality joins

A JOIN whose condition is two inequalities — interval overlaps,
point-in-range, as-of windows — was executed as a filtered CROSS JOIN.
Now it uses the sort-based IEJoin algorithm, by default:

SELECT count() FROM trades t JOIN quotes q ON t.time > q.window_start AND t.time < q.window_end;

Measured — 200K × 200K rows:

26.7: 112 sec. (cross join + filter)
26.8: 1.06 sec. (105x faster!)

— INNER, LEFT, RIGHT, FULL, SEMI, and ANTI joins are supported.

Developer: Vladimir Cherkasov.

parallel_full_sorting_merge

A merge join that runs on all cores: the input is sharded by the hash
of the keys into independent per-shard merge joins:

SET join_algorithm = 'parallel_full_sorting_merge';

Measured — 100M × 150M INNER JOIN, 32 threads:

algorithmtimepeak memory
full_sorting_merge5.9 s2.1 GB
parallel_full_sorting_merge1.5 s2.3 GB
parallel_hash20.4 s14.1 GB

— The streaming, low-memory nature of a merge join — at hash-join speed.

Developer: Alexey Milovidov.

Cascades optimizer 🧪

A cost-based optimizer for distributed query plans:

SET make_distributed_plan = 1, enable_cascades_optimizer = 1; EXPLAIN SELECT … FROM hits h JOIN dim d ON h.path = d.path GROUP BY … └──GatherExchange └──JoinLogical (Broadcast HashJoin) │ Join: h[10000] ⋈ d[20] -- cardinality estimates ├──ReadFromMergeTree (ParallelRead default.hits) └──BuildRuntimeFilter (Build runtime join filter on path) └──ReadFromMergeTree (ReplicatedRead default.dim)

— Chooses by estimated cost: shuffle / broadcast / replicated / local joins,
  one- or two-phase aggregation, two-stage top-N, parallel reads —
  inserting exchange operators as needed.

Developer: Alexander Gololobov.

Performance

Adaptive parallel GROUP BY

A new algorithm for parallel aggregation, on by default:
each thread aggregates into its own hash table until it holds
~16K keys, then freezes it:

— Frequent keys keep updating the small, cache-resident tables
  with no coordination.
— Rare keys are routed by hash into per-bucket backlogs
  and aggregated exactly once, in the bucket-parallel merge.

Measured — GROUP BY over 100M distinct keys with heavy states:

26.7: 0.81 sec.   26.8: 0.43 sec.
…and with an early LIMIT: 3.1 sec → 0.03 sec — up to 14x in CI perf tests.

Developer: Nihal Z. Miaji.

GROUP BY + LIMIT: a bounded heap

26.7 fused GROUP BY with ORDER BY LIMIT for sorted tables.
26.8 does it for any read order: a bounded heap during aggregation
prunes the groups that cannot appear in the result:

SELECT k, count() FROM events GROUP BY k ORDER BY k LIMIT 10; -- only ~10 groups are kept per thread, not 500 million

Measured — 500M rows, ~500M distinct keys:

26.7: 2.32 sec, 19.9 GB of memory.
26.8: 0.22 sec, 2.3 MB of memory.

Developers: Dmitriy Terenichev, Konstantin Bogdanov.

Aggregation, elsewhere

— Packed string keys: smaller hash-table cells for single-String
  GROUP BY keys — string-heavy aggregation up to 2x faster.

— Parallel single-level merge: when per-thread tables stay small
  but the merge dominates, it now runs in parallel.

— GROUP BY without aggregate functions uses HashSet-based methods:
  up to 1.8x faster; String keys skip a per-row placeholder write.

— DISTINCT: 2.4x faster when the stream is sorted by a prefix;
  partitioned tables aggregate each partition independently —
  the same trick now speeds up window functions and IN (subquery) sets.

— uniq, uniqExact, uniqHLL12 optimized without keys;
  groupUniqArray up to 3x faster.

Developers: H. Prabakaran, N. Z. Miaji, N. Taranov, A. Popov, Manuel.

Lazy reading of Parquet

For ORDER BY … LIMIT n over Parquet — on object storage, Iceberg,
and local files — the heavy columns are now read only for the n rows
that survive the LIMIT:

SELECT k, payload FROM s3('…/data.parquet') ORDER BY score DESC LIMIT 10; -- on S3: reads 3.3 MB instead of 171 MB — 51x less I/O, 8x faster

Measured on a local 880 MB Parquet file: 0.40 → 0.06 sec (6.5x).

— On by default; a file changed between the two passes is detected
  (FILE_CHANGED_DURING_READ) — no silently wrong results.

Developer: Alexey Milovidov.

Parquet reader improvements

More ways to skip data in the native Parquet V3 reader:

— Dictionary pruning: for equality and IN conditions, whole row groups
  are skipped when the dictionary page proves the value is absent —
  works where min/max statistics and bloom filters do not help.

— GeoParquet spatial pruning: row groups and pages whose bounding box
  does not overlap the query geometry are skipped.

— Tuple subcolumns: WHERE tup.1 = … prunes row groups and pages
  using the element's own statistics.

— Filter push-down through more type conversions
  (DateTime64, Decimal, Float32↔Float64); optional DECIMAL
  serialization of 128/256-bit integers enables pruning on them.

Developers: A. Milovidov, V. Chekalkin, M. Kolupaev, Groene AI, I. Babrou.

Parallel INSERT SELECT by default

The default of max_insert_threads changed from 1 to auto
(the number of CPU cores):

INSERT INTO dst SELECT hex(SHA256(toString(number))) FROM numbers_mt(20000000);

Measured (CPU-bound transform, 32 threads):

26.7: 1.9 sec.   26.8: 0.48 sec. (4x)

— Also parallelizes the write side of a plain INSERT where it is safe.
— Note: the number of created parts and the order of inserted rows
  can change; set max_insert_threads = 1 or compatibility = '26.7'
  to restore the old behavior.

Developer: Alexey Milovidov.

Faster everything

— Formatting Decimals as text: up to 190x for Decimal256
  (measured 5.3x on a mixed query); int-to-text 1.4x with AVX-512 IFMA.

— toStartOfInterval / time_bucket: up to 5x (measured 2.6x).

— Native protocol: String columns as offsets + bulk data —
  clients read them ~4x faster (negotiated by protocol revision).

— ZSTD decompression on x86_64: vectorized short-offset copies
  (the ARM counterpart shipped in 26.7).

— clickhouse-client skips a ping round trip before every query;
  client and local start faster (no accidental timezone table builds).

— ORDER BY pk LIMIT n over many parts reads only contributing parts
  (read_in_order_use_virtual_row on by default) — much less memory.

Developers: K. Bogdanov, Manuel, vahid-sohrabloo, A. Milovidov, N. Taranov.

AI Functions

aiSimilarity

Semantic similarity of two texts, straight in SQL:

SELECT aiSimilarity('The cat sat on the mat', 'A kitten rested on the rug', 'text-embedding-3-small') AS s; -- 0.87 — and ~0 for unrelated texts

— Embeds both texts with the configured provider and returns
  their cosine similarity in [-1, 1].
— Inputs are batched into one API request per block of rows.
— Credentials come from a named collection
  (ai_function_embedding_default_credentials).

Developer: David Meng.

aiRedact and aiFilter

aiRedact — scrub PII before the data leaves the database:

SELECT aiRedact(comment, ['email', 'name', 'phone']) FROM feedback; -- 'Contact [REDACTED] at [REDACTED]' — categories of your choice

aiFilter — a natural-language condition as a WHERE clause:

SELECT * FROM reviews WHERE aiFilter(text, 'the customer is asking for a refund');

Hardening, for all AI functions:
— Insecure (http) endpoints to remote hosts are denied by default.
— Outbound API calls are capped per query (default 1000).
— Truncated model responses are rejected, not silently returned.

Developers: David Meng, yanglongwei, George Larionov.

Bonus

Animated PNG

The PNG output format learned to make animations:
add a t column — and the result becomes the frames:

WITH 480 AS W, 360 AS H, 60 AS T, 48 AS ITER, number % W AS px, intDiv(number, W) % H AS py, intDiv(number, W * H) AS t, 2 * pi() * t / T AS theta, 0.7885 * cos(theta) AS cx, 0.7885 * sin(theta) AS cy, -- c orbits the circle (px - W / 2) / (H / 2.6) AS x0, (py - H / 2) / (H / 2.6) AS y0, arrayFold((acc, i) -> if(acc.3 >= 0, acc, -- z ← z² + c if(acc.1 * acc.1 + acc.2 * acc.2 > 4.0, (acc.1, acc.2, i), (acc.1 * acc.1 - acc.2 * acc.2 + cx, 2 * acc.1 * acc.2 + cy, -1))), range(ITER), (x0, y0, -1)::Tuple(Float64, Float64, Int64)) AS res, if(res.3 < 0, ITER, res.3) / ITER AS v, sqrt(v) AS w SELECT px AS x, py AS y, t, least(1.0, 2.2 * w * w) AS r, least(1.0, greatest(0., 1.8 * w - 0.35)) AS g, least(1.0, greatest(0., w < 0.6 ? 0.4 + 1.2 * w : 2.2 - 2.4 * w)) AS b FROM numbers_mt(480 * 360 * 60) FORMAT PNG

— A morphing Julia set: 10M pixels × 48 iterations, rendered in 1.4 sec →

Developer: Alexey Milovidov.

ClickHouse in your browser 🧪

The clickhouse binary now builds for WebAssembly
(wasm64, via Emscripten):

$ node clickhouse.js local -q " CREATE TABLE t (x UInt64) ENGINE = MergeTree ORDER BY x; INSERT INTO t SELECT number FROM numbers(1000000); SELECT sum(x) FROM t" -- a real ClickHouse, with real MergeTree tables — no server, no cloud

— clickhouse local runs queries under Node.js ≥ 24 and in the browser.
— A CI job pins the build; the WASM module is a build artifact.
— The SQL parser also builds standalone (utils/wasm-parser) —
  the same parser that powers syntax highlighting in the Web UI.
